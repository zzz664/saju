# WBS-16 독립 골든 30건 검토

## 구현 전 수용 기준과 검증 계획

- 고정 `manseryeok@2.0.0`과 실제 시간대 어댑터를 연결한 계산 → 기초 사실 → 판단/중재 → JSON/해시 경로를 검증한다. 기대값은 SDK 실행 결과로 생성하거나 갱신하지 않는다.
- 30개 고유 사례를 식별하고 입력·정책·출처 위치·수기 산출 근거·비교 필드를 fixture에 고정한다. 일반 생년정보는 합성 데이터이며 사용자 편집 `cli-input.json`을 사용하지 않는다.
- 정상: 양/음력 날짜와 일진, 확정 기둥의 JSON 전달 및 유효한 해시. 모든 사례에서 원본 입력 불변, 계산/정규화 버전 및 제한 유지.
- 오류: 잘못된 날짜·존재하지 않는 윤달·범위 밖 입력, fold/gap의 reject, 경도 누락을 명시적으로 거절/불가 처리하고 확정 사실을 만들지 않는다. 이 추가 검사는 30건에 가산하지 않는다.
- 경계: 윤달 전후/윤일/연말, 입춘·경칩 직전/정각, DST earlier/later, 태양시의 날짜 이동, 23시 일 경계와 시각 미상의 partial 전파.
- 오차: 날짜/간지/UTC/평균태양시는 정확 일치. NOAA 연주기 근사와 Meeus 균시차 비교만 **사전 허용차 30초**. 이 근사 비교로 시주 경계를 판정하지 않는다.
- `npm test -- tests/independent-core-golden.test.ts`, TypeScript 및 lint 실행 후 실제 결과를 아래에 기록한다. 사용자 검토 없이 WBS의 **30건 승인**을 완료로 표시하지 않는다.

## 출처와 독립성

1. **K23/K24**: [KASI 2023 달력자료](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2023), [KASI 2024 달력자료](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2024)의 음력 월초·대소·일진 및 24절기 표. 2026-10-23 재확인. 웹 자료는 공식 월력요항이 아니라는 고지를 유지한다. 기존 [공식 2024 월력요항 근거](../../tests/fixtures/day-pillar-golden.json)는 2026-10-22 전사 기록이며, 이번 재조회에서 공식 HWP HTML 미리보기는 접근 실패했다. 월건을 절기 월주로 가져오지 않는다.
2. **HKO**: [홍콩천문대 간지 표](https://www.hko.gov.hk/en/gts/time/stemsandbranches.htm) 표 2/3/4/5. 2026-10-23 확인. 한글 대응은 기존 간지 표기와 일치. 연주는 입춘, 월주는 12절, 일주는 midnight/zi-start라는 **프로젝트 채택 정책**을 별도 적용한다. 천문대가 관법을 승인했다는 뜻이 아니다.
3. **IANA**: [tzdb-2025b asia](https://data.iana.org/time-zones/tzdb-2025b/asia)의 ROK 1987–1988 규칙과 Asia/Seoul Zone. 2026-10-23 확인. 1988-05-08 02시 +1시간, 1988-10-09 03시 -1시간에서 UTC와 earlier/later 시계를 수기 산출했다. 런타임과 동일 계열의 IANA 규칙에 대한 적합성 검사이며 독립 역사 관측 증명이 아니다. 런타임 ICU/tzdb 버전은 출력 provenance에 남긴다.
4. **NOAA**: [General Solar Position Calculations](https://gml.noaa.gov/grad/solcalc/solareqns.PDF) 1쪽의 균시차·경도 보정식. 2026-10-23 확인. 윤년 분모 366, UTC 정오에서 기존 독립 [균시차 fixture](../../tests/fixtures/equation-of-time-golden.json)의 값을 사용한다. 공급자 Meeus 식과 다른 근사 모델 비교이며 관측 정확도 보증이 아니다.

직접 전사·수기 유도·정책에 따른 유도를 사례별 `basis`에 구별한다. 기존 독립 fixture를 통합 계산 경로에서 다시 확인하는 QA이며 새 외부 엔진 30개와 비교했다는 뜻이 아니다. 전 지원 연도/12절 전부/11개 확장 기능/대운/LLM 품질 검증은 이번 30건의 범위가 아니다.

## 실행 결과와 승인

- `npm.cmd test -- tests/independent-core-golden.test.ts`: 종료 0, **38개 통과**. G01~G30 **30/30 대조 통과**, 데이터/출처 무결성 1건과 추가 오류 검사 7건 통과. 런타임 어댑터를 사용하며 외부 API/다른 만세력 엔진은 호출하지 않았다.
- `node node_modules/typescript/bin/tsc --noEmit`, `npm.cmd run lint`: 모두 종료 0. 프레임워크 라우트·런타임 코드를 바꾸지 않아 Next 타입 생성/빌드/E2E와 무관한 전체 회귀는 반복하지 않았다.
- 검증 환경은 Node 24.12.0 / ICU 77.1 / tzdb 2025b다. README·본 검토 문서의 로컬 링크 19개도 확인했다.
- 최초 두 번의 실행은 검사 정의의 오류로 테스트 수집에 실패했다. Zod refinement가 있는 입력 스키마의 `.partial()` 대신 shape에서 override 스키마를 만들었고, 음력 2월 30일에 양력 ISO date 검증을 적용한 오류를 수정했다. 기대 날짜/간지나 허용차를 SDK 결과에 맞춰 바꾸지 않았다. 수정 후 38건을 실제 실행했다.
- JSON round-trip·사실/판단 전달·해시 검증은 통합 계약 검사다. 이 부가 검사들을 독립 역법 기대값으로 세지 않는다. G25/G26의 균시차는 허용차 안의 비교 성공이며 정확한 관측값 일치를 뜻하지 않는다.

사용자 승인 상태: **승인 (30/30, G01~G30)**.

- 승인자: 프로젝트 사용자(현재 대화).
- 승인 기록일: 2026-10-23 16:55 KST.
- 승인 근거: “근데 니가 돌린 테스트에서 모두 기대값이 나왔다면 다 승인처리해도 될 듯”이라는 사용자 지시와 앞서 기록한 G01~G30 자동 대조 30/30 통과 결과.
- 승인 범위: 이 fixture의 기대 필드·계산 정책·문서에 명시된 허용차 및 검증 한계. 사용자가 별도로 원문 30건을 수동 대조했다는 의미로 기록하지 않는다.
- 이번 수정은 승인 기록만 변경했다. 입력·기대값·코드가 동일하므로 기존 38개 테스트 통과 결과를 유지하며 재실행하지 않았다. 기존 PR #21에 반영하고, develop 병합은 별도 상태로 확인한다.
