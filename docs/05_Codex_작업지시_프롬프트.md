## C. 복사용 프롬프트 — WBS 한 건

```text
AGENTS.md, WBS.csv, 02_기술설계서.md, 이번 WBS의 필수 상세설계서를 읽어라.
현재 작업은 {WBS-ID} 단 하나다. develop에 직전 기능 PR 및 선행 WBS가 실제 머지되었는지 먼저 확인하라.
머지되지 않았다면 새 브랜치/코드 작성 없이 보고하고 중지하라.
머지가 확인되면 develop을 git pull --ff-only origin develop으로 최신화하고 병합된 로컬 기능 브랜치를 git branch -d로 안전 삭제하라.
feature/{WBS-ID}-<slug> 브랜치 하나를 만들고 한 기능의 코드·정상/실패/경계 테스트만 구현하라.
npm test와 해당 WBS의 필수 Mock/로컬 검증을 수행하라.
WBS-65~68 또는 OpenAI 연동은 21_실제_OpenAI_API_테스트_설계.md를 읽고, 실제 API 호출은 서버가 승인한 테스트 계정/환경에서 사용자가 설정 화면의 동의 후 '테스트 실행'을 클릭한 경우에만 허용하라.
사용자가 실호출을 승인하지 않은 경우 Mock만 수행하고 LIVE_NOT_RUN 또는 LIVE_BLOCKED로 정확히 기록하라. 실제 API를 호출했다고 추정하거나 테스트 성공을 조작하지 마라.
실호출 시 서버 키, 비용 한도, 개인정보 보호, 공급자 응답 상태를 확인하라. 다른 작업에서 임의 live 호출·실제 PG 청구·CI 설정은 금지한다.
docs/worklog.md에 변경 파일, 테스트 명령, Mock 결과, Live 상태 및 호출/토큰 증빙(있을 경우), 남은 제약을 기록하라.
develop 대상 PR 한 건을 생성하고 PR URL/상태/검증 결과만 보고한 뒤 즉시 중지하라.
```

## G. 완료 상태 보고 규칙

- `npm test`: PASS/FAIL/미실행을 구분한다.
- API 실험: `MOCK_PASS`, `LIVE_PASS`, `LIVE_FAILED`, `LIVE_NOT_RUN`, `LIVE_BLOCKED` 중 실제 상태를 적는다. 허용되지 않은 자동 실호출 금지.
- WBS 개발 종료, PR 생성, develop 머지, 실API 검증 완료는 **서로 다른 상태**이다.
- 사용자가 Live를 활성화하지 않아도 Mock 기능 작업은 진행 가능하나, **Live 검증이 완료되었다고 표시하지 않는다.** 릴리스 QA에는 미완료 live 항목을 명확히 보고한다.
