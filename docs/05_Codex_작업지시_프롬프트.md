# Codex 작업 지시 프롬프트 — v2.4 통합 실행 매뉴얼

> **이 문서만의 역할**: Codex에 **지금 어떤 WBS를 어떻게 지시할지**. 상세 기술 요구사항을 다시 복제하지 않는다. 코어·LLM·UI·OAuth·DB·테스트 PG·스트리밍·후속 질문 전부 `WBS.csv`에 정리되어 있다.

## A. 최초 1회 준비

1. 저장소 루트에 `AGENTS.md`(본 패키지 `04_AGENTS.md`의 내용)를 배치한다.
2. `WBS.csv`와 `02_기술설계서.md`, 해당 작업에 필요한 상세설계 문서를 Codex가 읽을 수 있는 경로에 배치한다.
3. 사용자와 **현재 마지막으로 `develop`에 병합된 WBS 및 PR**을 확인한다. 문서의 TODO 상태만으로 실제 완료를 주장하지 않는다.
4. 패키지 관리자는 **npm**. 새 저장소 구성이라면 WBS-00에서 초기화 대상·파괴적 작업 범위를 확인하고, 승인 후 WBS-18을 시작한다. **기존 저장소 보관/아카이브는 요구하지 않는다.**
5. **1기능 1브랜치 1PR**, PR 생성 후 중지, 사용자 리뷰·머지 전 다음 작업 금지. WBS-00의 읽기 전용 승인 점검은 개발 기능 PR이 아니다.

## B. 권장 실행 순서(단 하나의 실행표)

**기준 데이터는 `WBS.csv`의 `실행순서` 열**이다. 아래는 그 그룹 요약이며, 번호가 작은 WBS부터 기계적으로 실행하면 안 된다.

|단계|순서/작업|주의|
|---|---|---|
|0. 초기화|**00(승인 확인)** → 18|00은 읽기 전용 범위 확인. 삭제는 별도 승인 후|
|1. 코어|02 → 01 → 03 → 04 → 05 → 06 → 07 → 08 → 09 → 10 → 11 → 12 → 13 → 14 → 20 → 22 → 23 → 24 → 47 → 16 → 25 → 17 → 26|모든 행은 독립 1PR; 47=R01 페르소나|
|2. 명리 확장|**27 → 28 → … → 46**|M01~M09, F01~F11; 11개 기능 전체|
|3. UI/계정|**48 → 49 → 50 → 51 → 52 → 53 → 54**|50/51 P06은 자리표시자만; 정적 리포트 완성 금지|
|4. 메신저형 풀이|**60 → 61 → 62 → 63 → 64**|DB 상태 → R02 실제 SSE → P06 말풍선 → R03 질문 → QA|
|5. 테스트 결제|**55 → 56 → 57 → 58 → 59**|운영 키/실제 청구 절대 금지|
|6. 배포 검증|**15 → 21**|로컬 전체 검사·RLS/OAuth/SSE/PG 환경 검증|
|선택|19|사용자 별도 승인 시에만 CI 구성|

**선행 WBS가 병합되지 않았다면 해당 WBS를 시작하지 않는다.** 현재 프로젝트가 이미 개발 중이면 완료된 선행 항목을 다시 구현하지 말고, 실제 `develop` 기준으로 다음 미완료 항목만 택한다.

## C. Codex 복사 프롬프트 — 일반 WBS 1건

```text
AGENTS.md와 WBS.csv, 02_기술설계서.md 및 이번 WBS 관련 상세설계 문서를 읽어라.
이번 작업: {WBS-ID} 단 하나. 먼저 선행 WBS가 develop에 머지되었는지 확인하라.
직전 기능 PR과 선행 PR이 미병합이면 코드·브랜치를 만들지 말고 상태만 보고하라.
머지가 확인되었다면 develop 최신화 후 병합된 로컬 기능 브랜치를 git branch -d로 안전 정리하라.
latest develop에서 feature/{WBS-ID}-<slug> 브랜치 한 개를 만들어 이번 기능만 구현하라.
먼저 이번 WBS의 완료 조건과 테스트(정상/오류/경계)를 정의하고 코드를 구현하라.
npm test와 이번 기능의 필수 추가 검증을 실행하라. 결과·제약·변경 파일을 docs/worklog.md에 기록하라.
기존 코어·11개 기능·캐릭터·대화형 풀이·OAuth·테스트 결제 원칙을 위반하지 마라.
임의의 CI 구축, 라이브 PG 전환, 실제 OpenAI API 호출, 비밀키 변경은 하지 마라.
develop 대상 PR 한 건을 생성하고 PR 번호/검증 결과를 보고한 뒤 즉시 중지하라.
```

## D. PR 리뷰에서 수정이 발생했을 때(동일 PR)

```text
현재 열린 {PR 번호}는 아직 develop에 머지되지 않았다.
해당 기능 브랜치에서 리뷰 피드백만 수정하고, 관련 테스트를 다시 실행하라.
같은 PR을 업데이트하고 docs/worklog.md에 변경 및 테스트 결과를 기록하라.
새 브랜치·새 PR·다음 WBS 구현은 하지 마라. 리뷰 대기 후 중지하라.
```

## E. 사용자 머지 후 다음 작업 재개

```text
직전 {PR 번호}가 GitHub에서 develop에 실제 MERGED인지 확인하고 origin/develop 반영도 점검하라.
미병합이면 아무 코드 변경 없이 보고하고 중지하라.
병합 확인 후 git checkout develop && git pull --ff-only origin develop을 실행하라.
지난 로컬 기능 브랜치는 git branch -d로 삭제하되 안전 삭제가 실패하면 강제 삭제하지 말고 보고하라.
WBS.csv의 실행순서와 선행작업을 확인한 뒤 사용자 지정 {다음 WBS-ID} 한 건만 C 절대로 진행하라.
PR 1개를 만들고 즉시 중지하라.
```

## G. 특별 금지 사항

- v2.4 메신저형 P06을 정적 리포트 JSON 화면으로 대체하지 않는다.
- `report.completed`를 문자열 마지막 청크 수신만으로 판정하지 않는다. **검증·저장·커밋된 DB 상태**를 기준으로 한다.
- 문서 안의 예시 캐릭터나 참고 이미지의 서비스명을 실제 제품명으로 확정하지 않는다.
- `WBS.csv`의 미완료 작업을 병렬로 수행하지 않는다.
- 테스트를 실패 무시 옵션으로 통과시킨 척하거나 CI 통과를 완료의 필수 조건으로 되돌리지 않는다.
