# 기획서 — v2.4 통합 기준(최적화본)

## 1. 제품 목표와 범위

사용자 출생 정보를 정확한 역법으로 계산하고, 전통 명리학의 **출처가 추적되는 결정적 판단**을 생성한다. 이를 **가상의 캐릭터가 자연스러운 한국어로 설명하는 메신저형 말풍선**에 실제 스트리밍으로 보여준다. 전체 풀이가 완료되면 **같은 풀이의 근거에 대한 후속 질문**을 허용한다. 서비스·상품·캐릭터의 최종 명칭은 확정하지 않는다.

## 2. 확정 의사결정

- 패키지 관리자 **npm**, `package-lock.json` 커밋. pnpm 및 잠금 파일 혼용 금지.
- 프레임워크 **Next.js App Router + TypeScript**, 입력·출력은 Zod, 테스트는 Vitest. 웹 프레임워크와 무관하게 실행 가능한 순수 도메인 코어 유지.
- 만세력 **`yhj1024/manseryeok` 고정 선택**. 대체 라이브러리 선정·비교 작업 금지. 실제 버전·타입 확인 후 어댑터에서만 사용하며, 경계·독립 골든 테스트를 개발과 병행.
- 명리학 계산·판단은 근거·예외·충돌·버전을 기록하는 규칙 엔진. **LLM은 계산·명리 판단을 새로 하지 않음.**
- LLM **`gpt-4o-mini`**, 서버 전용 Responses API. R01 캐릭터 설정은 문체에만 관여. **사용자 풀이 화면은 R02 실제 스트리밍 말풍선**, 전체 검증·저장·완료 후 **R03 후속 질문 허용**.
- 모든 화면 **모바일 퍼스트 + 반응형**, 업로드 이미지의 색상만 참고; **일러스트 및 특정 브랜드 자산 사용 금지**. 서비스명·상품명·캐릭터명은 미정.
- **Supabase Auth(Google/Kakao) + PostgreSQL/RLS + 저장 기능은 서비스 범위에 포함**. PG는 **테스트 환경만**, 실제 청구·운영 키 금지. 배포는 Vercel 후보.
- 기능 개발 시 **1개 WBS = 1개 기능 브랜치 = 1개 PR**(`develop` 대상). PR 생성 뒤 중지; 사용자 리뷰·`develop` 머지 확인 전 다음 기능 착수 금지. 머지 뒤 `develop` 갱신 및 `git branch -d`로 안전 정리.
- **GitHub Actions CI는 초기 필수 아님**. 각 WBS의 로컬 테스트, 결과 기록(`docs/worklog.md`), 사용자 리뷰는 필수. 릴리스 전 `npm test`, 타입·린트·빌드, 연동·보안 QA를 실시.
- 기존 저장소를 보관·아카이브하는 워크플로는 요구하지 않는다. **삭제·강제 푸시·DB 파괴·시크릿 변경은 대상과 범위를 명시해 별도 승인**받는다.


## 3. 핵심 사용 흐름

`기능 선택(F01~F11) → 로그인(Google/Kakao) → 출생 정보 입력/선택 → 계산 정책 검증 → 사주 원국/결정적 판단 JSON 생성 → 접근권 확인 → 캐릭터 말풍선 실시간 스트리밍 → 전체 섹션 검증·저장 → 질문 입력 활성화 → 동일 분석 근거로 대화 이어가기 → 보관함 재조회`.

초기 회원 기반 저장형 대화를 기준으로 한다. 비회원 무료 체험의 저장·후속 질문 여부는 미정이며 인증된 대화 API를 비회원에게 노출하지 않는다. 테스트 결제는 선택 기능의 권한 검증 경로로 구현하되 사업 가격·상품 정의는 확정하지 않는다.

## 5. 화면/디자인

P01~P18 라우트를 유지하며, **P06 `/results/[analysisId]`는 정적 리포트가 아닌 채팅 화면**이다. 캐릭터는 왼쪽, 사용자는 오른쪽 말풍선; 최초 풀이 중 입력창 비활성, 서버의 `report.completed`를 재조회로 확인한 뒤 활성화한다. 320/360/390/430/768/1024/1440px 점검. 라벤더·인디고·퍼플·피치 계열 토큰만 사용하고 일러스트는 배제한다.

## 6. 비기능/안전 요구

- 출생시각 미상·윤달·절기·자시·역사 시간대·태양시 정책을 정확하게 드러낸다. 임의 값으로 채우지 않는다.
- 최초 리포트와 후속 답변 모두 현재 분석의 `FeatureResult`를 최상위 명리 근거로 사용하며 타인의 숨은 심리/확정적 미래 사건을 단정하지 않는다.
- 스트리밍 텍스트는 완료 전 화면에 노출되는 한계가 있다. 명리 판단 선검증·섹션별 상한·위험 신호 중단·완료 후 검증을 적용한다.
- 저장형 대화는 본인 소유 및 이용 권한 확인, RLS, 멱등성, 질문 횟수/비용 제한을 강제한다.
- 실 API·OAuth·PG 연동은 별도 자격증명과 외부 콘솔 설정이 필요하며, 문서 자체가 연동 완료를 뜻하지 않는다.

## 7. 범위 구분 및 완료 기준

기존 **6주 코어 엔진 계획**은 코어 품질 검증 목표로 유지하지만, 11개 해석·인증·스트리밍·결제까지 포함한 전체 서비스를 6주 안에 완성한다고 약속하지 않는다. WBS 순서는 `WBS.csv`의 `실행순서`를 단일 기준으로 한다. 각 작업은 로컬 테스트·기록·PR 리뷰·머지 게이트를 만족해야 완료된다.
