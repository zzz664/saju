# WBS-17 계산·서술 QA 및 코어 문서 검증

## 완료 조건과 검증 계획

- 기준: 최신 develop의 PR #24 merge `b5293423c0d149b3176acc84e2a78768a3b711bb`. WBS-16/#21, WBS-25/#22도 GitHub MERGED 및 origin/develop ancestor 확인. 실행순서 26인 WBS-17만 수행한다.
- 정상: 기존 독립 골든 30건, 계산/판단/중재/해시 회귀, 승인형 R01 Mock 180건, 입력·근거·문체·모델 설정 계약, 실제 로컬 개발자 화면/API 경로가 통과해야 한다.
- 오류: 위조/누락 입력·윤달/DST reject·불확실성 전파·근거 이탈·공급자 오류·무권한/비용/동시성 차단을 기존 테스트로 검사한다. 문서 링크 검사는 누락/잘못된 경로를 실제 파일 존재 여부로 검사한다.
- 경계: 윤달/절입/자시/태양시/DST, 시각 미상의 partial/unavailable, 100회 해시 결정성, 예산 한도, 문체 변경 시 분석 불변, HTTP/usage 오류를 검증한다.
- 사용자 편집 `cli-input.json`, next-env.d.ts, .env/키/실제 장부를 변경하지 않는다. 고정 회귀 fixture와 수동 CLI 입력을 분리해 개인 입력이 테스트/로그에 사용되지 않도록 한다.
- 품질 평가는 자동 구조·근거 ID/Mock 인용 검사와 사람 의미/자연스러움 평가를 구분한다. 실제 API는 새로 호출하지 않으며 기존 사용자 보고 LIVE_FAILED를 LIVE_PASS로 바꾸지 않는다.
- P0 기준: 검사 범위 내 잘못된 확정 계산, 미상 정보 확정 승격, 근거/소유권/예산 우회, 자동 실호출·비밀 노출 등 제품 핵심 계약 위반. 문체 실패·미평가·향후 기능은 개별 상태와 심각도를 기록한다. 미실행 검사를 통과로 간주하지 않는다.

## 범위와 재현

현재 구현은 기초 원국·20개 판단/중재·개발자용 R01까지다. M01~M09/F01~F11 확장, Supabase/OAuth/RLS, P06/R02/R03, PG 및 배포 QA는 해당 선행 WBS에서 검증한다. 이 문서는 전체 제품 출시 승인이나 향후 기능 완료 증빙이 아니다.

```sh
npm test -- --maxWorkers=1
npm run check:docs
npm run test:e2e:core-qa
node node_modules/typescript/bin/tsc --noEmit
npm run lint
```

Mock 품질 재평가는 임시 사본에서 `npm run eval:persona`로 실행하고 비식별 집계만 아래 기록한다. 원본 WBS-25 평가 산출물과 사람 승인 기록을 덮어쓰지 않는다. E2E는 전용 임시 프로젝트에서 빌드/route typegen/tsc와 production 차단까지 검사한다.
`test:e2e:core-qa`는 기존 계산 개발자 화면과 API 테스트 화면을 같은 격리 사본에서 함께 실행하고 production 빌드는 한 번만 수행한다. E2E/빌드 프로세스에는 빈 OpenAI 키와 Live=false를 명시한다.

## Mock 서술 품질과 잔여 사항

현재 프롬프트 1.0.1, 기본 모델 메타데이터 gpt-4o-mini로 재실행한 [비식별 집계](WBS-17-mock-quality-summary.json)는 **180/180 완료, 실패 0, 문체 플래그 0, MOCK_PASS**다. 30사례(complete 20 / partial 4 / unavailable 6) × 2개 합성 문체 × 3회이며, 60개 반복 그룹은 모두 동일한 출력을 냈다. 각 문체의 90개 출력 중 고유 출력은 9개, 고유 도입문은 2개다. 사례별 대표 30개에서도 반복 도입문은 28개로, 실제 모델의 표현 다양성을 검증한 결과가 아니다.

- 사람 의미/자연스러움/가독성 평가는 **0/60**, 평균 **null / NOT_PERFORMED**로 유지한다. 목표 4점 달성을 주장하지 않는다.
- 추가 실제 OpenAI 호출은 **0회 / LIVE_NOT_RUN**이다. 사용자가 과거 보고한 completed/usage 및 문체 실패는 **LIVE_FAILED**로 남으며, 이번 프롬프트/모델 설정의 실제 품질 회귀도 미실행이다.
- QA-05의 합쇼체 프로필 지시 불일치(P1), QA-06의 거절 사유 상세화(P2)는 잔여 개선 항목이다. 자동 문체 합격이 이 문제의 해결이나 상용 품질 승인을 의미하지 않는다.
- 검사한 **현재 구현 코어의 관측된 P0 결함은 0건**이다. 위 미평가·잔여 항목과 향후 서비스 기능의 검증을 포함한 출시 승인은 아니다.

문서/회귀 검증 산출물만 갱신하며 WBS.csv의 과거 TODO를 일괄 완료로 바꾸지 않는다. PR 병합 여부는 실제 GitHub 상태와 develop 반영으로 판단한다.
