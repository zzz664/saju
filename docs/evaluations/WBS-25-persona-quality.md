# WBS-25 R01 반복 품질 평가

## 구현 전 수용 기준

- 합성 고정 사례 30개 × 서버 등록 합성 페르소나 2종(해요체/합쇼체) × 반복 3회 = 180회. 반복 수는 2~3회만 허용한다. 기존 R01 비스트리밍 JSON과 WBS-24 예산/접근 가드를 그대로 사용한다.
- 사례는 승인된 WBS-16 입력 중 20개와 시각 미상/절기 경계 4개, 경도 누락·DST reject·역법 불가 6개다. 역법 골든 승인을 문장 품질 승인으로 전용하지 않는다.
- 정상: 출력 스키마·알려진 근거 ID·원문 assertion 인용·원래 제한/상태·분석 키·버전·입력 불변. 페르소나 간 기초 데이터는 같고 표현/서술 키는 달라야 한다.
- 오류: 잘못된 평가 설정·중복 사례/페르소나·위조 코어/주입 필드·공급자 거절/불완전/오류·스키마/근거 이탈·실 공급자/production/예산 차단을 검사한다. 실패를 샘플에서 빼지 않고 고정 오류 코드로 기록한다. 원문 예외는 출력하지 않는다.
- 경계: 시각 미상의 partial, 설명할 근거가 없는 unavailable, 다른 일 경계/절기/DST·태양시 입력, 정확한 반복 2/3회와 예산 상한, 반복 도입/동일 문장.
- 구조/근거 검사와 문체 휴리스틱은 별도 결과다. 실패 샘플도 분모에 포함하고 실행 도구는 계약 실패가 있으면 종료 1이다. 템플릿 반복 지표·휴리스틱이 사람 평가나 환각 부재 증명은 아니다.
- 실 OpenAI 호출·계정/키 변경·다른 모델/자동 LLM 채점은 수행하지 않는다. 모델 메타는 기존 지정 `gpt-4o-mini`, 공급자는 명확히 `mock`이다. P06/R02/R03·11개 확장 기능의 품질 판정은 범위 밖이다.

## 사람 평가 기준

두 명 평가를 권장한다. 생성되는 검토 문서에서 원래 판단/제한과 해요체·합쇼체 샘플을 함께 읽는다. 자연스러움과 가독성을 각각 1~5점으로 평가하며 **각 평균 4점 이상**이 설계의 초기 목표다. 의미 변경/없는 사실 보충/불확실성 은폐가 있으면 점수와 별도로 실패를 표시한다.

|점수|자연스러움|가독성|
|---|---|---|
|1|문장이 부자연스럽고 말투가 자주 섞임|핵심 의미나 제한을 이해하기 어려움|
|2|상투구·반복·어색한 연결이 많음|긴 문장/용어 때문에 여러 번 읽어야 함|
|3|뜻은 전달되나 기계적인 표현이 남음|대체로 읽히지만 설명/구성이 더 필요함|
|4|문맥과 높임말이 자연스럽고 반복이 적음|관찰과 제한을 쉽게 구분할 수 있음|
|5|간결하고 일관되며 사례에 잘 맞는 표현|처음 읽어도 핵심과 한계를 명확히 이해함|

점수·평가자·평가일은 사람이 작성하기 전까지 비어 있다. Mock 반복 성공을 실제 GPT-4o mini 평가 점수로 바꾸지 않는다. 같은 사례/페르소나의 세 반복이 완전히 같으면 검토 문서는 한 샘플로 묶되 반복 수와 동일 여부를 표시한다.

## 실행 및 결과

프로젝트 루트에서 실행한다. PowerShell 실행 정책이 npm.ps1을 막으면 `npm.cmd`를 쓴다.

```sh
npm run eval:persona
npm test -- tests/persona-evaluation.test.ts tests/persona.test.ts tests/narration.test.ts tests/experiment-guard.test.ts
node node_modules/typescript/bin/tsc --noEmit
npm run lint
```

고정된 [평가 manifest](../../tests/fixtures/persona-evaluation-cases.json)와 합성 문체 설정만 사용한다. 임의 출생 파일·프롬프트·공급자·출력 경로 옵션은 받지 않는다. 현재 CLI는 production 차단용 NODE_ENV와 서버 OPENAI_MODEL 설정을 사용하며 .env/.env.local을 로드한다. 실제 API 키를 참조해 Provider를 선택하지 않고 항상 Mock으로 실행한다. WBS-66의 공통 모델 설정/프롬프트 변경 이후 재실행은 별도의 시점별 평가이며 아래 과거 산출물을 소급 갱신하지 않는다. 예산 가드는 로컬 평가 ID/세션·10분 기한·180회 상한으로 적용한다. 단가 1 microUSD/백만 추정 토큰은 Mock 예약 검증용 값이며 실제 요금이 아니다.

생성 산출물:

- [결과 JSON](WBS-25-persona-quality-results.json): 180행의 성공/실패·고정 오류 코드·근거/문장·서술/분석 키, 30개 원래 판단/제한·실제 버전, 합성 프로필/spec·프롬프트/평가 정책 버전. raw 출생 입력·키·요청 원문은 저장하지 않는다.
- [읽기용 샘플](WBS-25-persona-quality-samples.md): 사례별 원래 관찰/제한과 두 문체를 함께 표시한다. 사례/문체당 동일한 세 출력은 한 번만 보여 주고 반복 수를 기록한다. 서로 다르면 모든 출력을 남긴다. 생성 파일은 재실행 시 덮어쓰므로 사람 채점은 아래 별도 기록에 남긴다.

|검증|2026-10-23 결과|
|---|---|
|사례 상태|complete 20 / partial 4 / unavailable 6|
|30사례 × 2문체 × 3회|180/180 계약 대조 통과, 실패 0|
|근거 ID·Mock 원문 인용·상태/제한·분석 키/버전|불일치 검출 0|
|기존 문체 휴리스틱|180회 중 지적 0, 의미/안전/자연스러움 보증 아님|
|동일 사례·문체의 반복 3회|60개 조합 전부 동일 출력|
|문체별 서로 다른 전체 출력|각 90회 중 9종|
|문체별 첫 문장|각 90회 중 2종, 첫 발생을 제외한 중복 88회|
|반복을 빼고 사례당 하나만 본 첫 문장|각 30사례 중 2종, 첫 발생을 제외한 중복 28건|
|사람 자연스러움/가독성·의미 평가|미실시, 평균 점수 null|
|실 GPT-4o mini·F02/F05/F09·R02/R03|미실시/미구현, 실 API 승인 없음|

**높은 반복성은 Mock의 한계로 남긴다.** Mock이 원문 assertion을 인용하는 것은 한국어 용어를 쉽게 풀거나 실제 모델의 생성 변동성을 재현하는 평가가 아니다. 휴리스틱 지적 0을 문장 품질 합격으로 해석하지 않는다. 원문 인용 일치 검사는 Mock 계약에만 유효하며 인용 밖 문장의 의미나 환각은 사람 검토가 필요하다. 기존 Mock의 문구를 바꿔 지표를 좋게 만들지 않았다.

기본 도구는 계약 실패 또는 문체 휴리스틱 지적이 있으면 종료 1, 정상 Mock 결과면 종료 0이다. 실패도 분모에 포함하며 거절/불완전/오류를 자동 재시도하지 않는다. stdout은 집계 수치만, 예외는 고정 실패 문구만 출력한다. production 또는 `--live` 같은 미지원 인수는 실행 전 거절하고 산출물을 변경하지 않는다.

최초 도구 실행은 샌드박스의 tsx Windows 사용자 정보 조회에서 `uv_os_get_passwd / ENOMEM`으로 실패했다. 코드/검증을 우회하지 않고 승인된 샌드박스 밖에서 동일한 로컬 명령을 실행해 180회 대조가 정상 종료한 것을 확인했다. production/미지원 옵션의 종료 1과 산출물 불변도 같은 환경에서 검증했다.

관련 회귀 4파일/105개(신규 16 + 기존 89) 통과 후 서로 다른 반복 출력을 모두 남기는 검사를 추가했다. 최종 신규 17개와 TypeScript/lint가 통과했다. 로컬 링크 22개, 결과의 고유 실행 ID 180개, 원본 출생 입력 키 부재를 확인했다. Node 24.12.0 / ICU 77.1 / tzdb 2025b에서 검증했다.

## 사람 평가 기록

평가자·평가일·대상 출력 digest·자연스러움/가독성 점수·의미 변경/추가 주장/불확실성 은폐 유무·메모를 별도 기록한다. 두 문체 각각의 평균을 확인하며 미평가 항목은 점수 분모에서 숨기지 말고 미완료로 표시한다. 세 반복이 동일해 한 샘플만 읽는 경우 그 근거와 반복 묶음을 명시한다.

- 평가자: 미지정. 평가일: 미실시.
- 평가 완료 수: 0/60 사례·문체 조합 (각 3회는 동일한 Mock 출력).
- 자연스러움·가독성 평균: 미산출. 사람 의미 평가: 미실시.
- 실 모델/API 평가: 별도 승인 전 미실시. 이번 Mock 결과의 승인이 향후 실호출·고객 풀이 품질 승인으로 전환되지 않는다.

공식 참고: [OpenAI Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)의 과업별 목표/일반·경계·적대 사례와 사람 평가 병행 지침을 참고했다(2026-10-23 확인, OpenAI Docs 스킬 사용). 일반 원문 로그 수집 권고는 이 프로젝트의 개인정보 최소화 규칙에 따라 적용하지 않는다.
