# CI / 로컬 검증 정책 — v2.4

## 판단

**GitHub Actions CI는 초기 개발 완료/PR 머지의 의무 조건이 아니다.** 과거 CI 설정 실패 때문에 전체 개발을 중단하지 않도록 한다. 그러나 코드 테스트는 필수이고 실패를 숨기지 않는다.

|시점|필수 검증|비고|
|---|---|---|
|매 WBS PR|`npm test` + WBS별 계약/골든/Mock/화면 테스트 + `docs/worklog.md`|로컬 성공 결과와 리뷰|
|배포 전 WBS-15|`npm test`, `npm run typecheck`, `npm run lint`, `npm run build`|실제 package.json 스크립트가 존재해야 함|
|서비스 통합 WBS-21/59/64|OAuth/RLS/SSE/PG E2E·보안|자격증명 없으면 Mock vs 실제 검증 분리|
|선택 CI WBS-19|`npm ci` → `npm test`|별도 승인 시 도입|

## npm 사용 원칙

- `package-lock.json`을 Git에 커밋한다. 로컬에서는 `npm install`, CI에서는 `npm ci`를 사용한다.
- Node.js 버전은 `engines`/`.nvmrc`/CI에서 맞추고 패키지 버전은 lockfile 기준으로 재현한다.
- 기존 `pnpm-lock.yaml`, `yarn.lock`과 혼용하지 않는다.
- 테스트가 전혀 없는 상태를 통과시키는 옵션을 사용하지 않는다.

## 선택적 GitHub Actions 샘플 (기본 비활성)

```yaml
name: unit-tests
on:
  pull_request:
    branches: [develop]
jobs:
  unit-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm
      - run: npm ci
      - run: npm test
```

실제 Node 버전·패키지 스크립트 확인 및 사용자 승인이 끝난 뒤에만 추가한다. GitHub Rulesets/Branch protection에 기존 필수 상태 검사가 남아 있다면 CI를 삭제하더라도 PR이 막힐 수 있으므로 관리 화면에서 정리한다. **CI 검사를 우회해 테스트 실패를 숨기지 않는다.**
