# 임시 UI 디자인 설계 — v2.4

> 목적: 업로드된 참고 이미지의 **색감과 분위기만 참고**하여, 코어 기능 검증에 사용할 임시 UI 설계를 정의한다.  
> 비목적: 참고 이미지의 **일러스트, 캐릭터, 문구, 화면 배치, 서비스명, 브랜드 자산을 복제하지 않는다.**

## D-1. 디자인 반영 범위

- **반영한다**: 라벤더·퍼플·인디고 중심의 메인 컬러, 크림 화이트 배경, 피치/골드 포인트, 둥근 카드, 부드러운 그림자, 밝고 몽환적인 그라데이션 분위기.
- **반영하지 않는다**: 여우/인물 일러스트, 특정 브랜드명, 문구, 카드 제목, 아이콘 조합, 히어로 구조 그대로의 복제.
- **결정 원칙**: 코어 기능 검증이 목적이므로, 화면은 심미성보다 정보 전달과 기능 흐름 검증에 우선한다.

## D-2. 이미지 기반 색상 토큰(임시)

업로드 이미지에서 시각적으로 추출한 대표 색상(예시):

- `#F4EDF5` 소프트 아이보리 라벤더
- `#A99EE1` 라이트 라벤더
- `#685DE4` 비비드 퍼플 블루
- `#916FEE` 퍼플 포인트
- `#D4B1DE` 핑크 라벤더
- `#F5D5A8` 소프트 골드/피치
- `#ECA160` 웜 피치 오렌지
- `#67639B` 뮤트 인디고
- `#1C1A1C` 텍스트용 다크 컬러

## D-3. 모바일 퍼스트 레이아웃 원칙

모든 화면은 **모바일 퍼스트**를 기준으로 설계한다.

### 브레이크포인트

- `sm`: 360~479px
- `md`: 480~767px
- `lg`: 768~1023px
- `xl`: 1024px+

### 공통 규칙

1. 기본 레이아웃은 **1열 스택 구조**로 시작한다.
2. 주요 CTA는 화면 하단 또는 첫 화면 내에서 1회 이상 노출한다.
3. 모바일에서는 카드 간격 12~16px, 섹션 간격 24~32px를 기본으로 한다.
4. 태블릿 이상에서만 2열 이상의 카드 그리드를 허용한다.
5. 데스크톱은 모바일 화면을 단순 확대하지 않고, 카드 폭 제한과 정보 밀도를 재조정한다.

### 컨테이너

- 모바일: 좌우 패딩 16px
- 태블릿: 좌우 패딩 24px
- 데스크톱: 최대 폭 1200px, 좌우 패딩 32px

## D-4. UI 컴포넌트 가이드(임시)

### 버튼
- 높이: 모바일 48px 기본
- 모양: radius 999px(필 버튼), 보조 버튼은 radius 16px 허용
- Primary: `gradient.primary`, 흰색 텍스트
- Secondary: 흰색 배경 + `primary.600` 텍스트 + 은은한 보더

### 카드
- radius 20~24px
- background: `bg.elevated`
- border: `border.subtle`
- shadow: `0 8px 24px rgba(104, 93, 228, 0.10)` 수준의 소프트 섀도우
- 카드 내부 패딩: 16px(모바일) / 20px(태블릿 이상)

### 상단 헤더
- 모바일: 높이 56~64px
- 좌측 브랜드/서비스명 영역, 우측 검색/메뉴 또는 액션 버튼
- 스크롤 시 반투명 배경과 블러 효과 허용

### 탭/카테고리 칩
- 높이 36~40px
- 기본: `bg.subtle`
- 활성: `primary.600` 배경 또는 `primary.500` 틴트 배경 + 진한 텍스트

### 입력 폼
- 높이 48px 이상
- radius 14~16px
- 에러/도움말 텍스트를 명확히 구분
- 출생시간 미상 등의 선택값을 체크/토글로 명시

## D-5. 정보 구조 권장안

코어 검증용 UI는 아래 5개 화면군만 먼저 설계한다.

1. **입력 화면**: 생년월일, 음양력, 윤달, 출생시각, 출생지, 기능 선택
2. **결과 요약 화면**: 핵심 결과 요약, 주의사항, 상세 보기 진입
3. **원국/명리 상세 화면**: 연월일시주, 오행, 십성, 판단 근거
4. **기능별 풀이 화면**: P06 실시간 메신저형 말풍선(최초 서술 완료 후 후속 질문)
5. **개발자 검증 화면**: JSON 보기, 규칙 버전, 계산 정책, LLM 입력/출력 검토

## D-6. 반응형 화면 동작 규칙

### 입력 화면
- 모바일: 단일 컬럼 폼 + 스티키 하단 CTA
- 태블릿: 입력 영역과 가이드 영역 2열 분리 가능

### P06 대화형 풀이 화면
- 모바일: 상단 상태/근거 버튼 + 스크롤 말풍선 목록 + 하단 입력 composer(최초 보고서 완료 전 비활성)
- 태블릿/데스크톱: 중앙 대화 목록 최대 720px, 근거/상태는 보조 패널(선택)

### 기능 선택 화면
- 모바일: 2열 이하 아이콘 그리드 또는 가로 스크롤 칩
- 데스크톱: 4열 카드 그리드까지 허용

## D-7. 구현 권장 방식

Next.js에서는 **디자인 토큰을 먼저 정의한 후 컴포넌트를 조립**한다.

추천 구조:

```text
src/
├── styles/
│   ├── tokens.css
│   ├── theme.css
│   └── globals.css
├── components/
│   ├── ui/
│   │   ├── Button.tsx
│   │   ├── Card.tsx
│   │   ├── Input.tsx
│   │   ├── Chip.tsx
│   │   └── Section.tsx
│   └── layout/
│       ├── MobileHeader.tsx
│       ├── BottomNav.tsx
│       └── ResponsiveContainer.tsx
```

- 색상값을 컴포넌트 안에 하드코딩하지 않고 CSS 변수 또는 토큰 파일에서 참조한다.
- 임시 시안 단계에서는 Tailwind를 쓰더라도 `theme.extend.colors` 또는 CSS 변수로 색상을 관리한다.
- 일러스트/배경 이미지는 기본적으로 사용하지 않는다. 필요한 경우에도 단색 또는 추상 그라데이션만 사용한다.

## D-8. 접근성 및 품질 기준

1. 본문 텍스트 대비비는 WCAG AA를 목표로 한다.
2. 주요 버튼은 색상만으로 상태를 구분하지 않는다.
3. 모바일 기준 터치 영역은 최소 44px 이상.
4. 기능 검증용 화면이므로 애니메이션은 200~250ms 이하의 짧고 단순한 수준으로 제한.
5. LLM 결과 텍스트는 길이가 길어질 수 있으므로 line-height 1.6 이상, 문단 간격 12~16px 유지.

## D-9. Codex 구현 지시 요약

- 참고 이미지의 **색감만** 사용하고, 일러스트·문구·브랜드·레이아웃을 복제하지 않는다.
- 모바일 퍼스트로 구현한다.
- 반응형은 `sm/md/lg/xl` 기준으로 구현한다.
- 초기 목표는 미려한 마케팅 랜딩이 아니라 **사주 코어 검증에 적합한 임시 UI**다.
- 기능 개발 원칙은 동일하게 **1기능 1브랜치 1PR**, develop 머지 확인 후 다음 작업 진행.

## D-10. P06 v2.4 대화형 UI 표준

- 캐릭터 말풍선은 왼쪽, 사용자 말풍선은 오른쪽; `bubble.delta`마다 텍스트 증가. 단순 타이핑 효과 시뮬레이션으로 실제 스트림을 대체하지 않는다.
- 서버 `report.completed`와 후속 GET 완료 상태 검증 전에는 질문 입력창을 잠근다. 중단/오류/재시도/새 메시지 표시 포함.
- 모바일 composer는 키보드·safe-area를 고려, 자동 스크롤은 하단 가까운 경우만 사용. `aria-live` 토큰 단위 반복 알림 금지.
- 구현 책임: WBS-62. WBS-50/51은 임시 화면/라우트 골격만 두며 정적 P06 UI를 구현 완료로 간주하지 않는다. 상세 와이어프레임: `14`, 스트리밍 구현: `19`.
