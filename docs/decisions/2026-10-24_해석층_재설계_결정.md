## 1. 문제

1. `AGENTS.md`의 "LLM은 확정된 판단만 설명"과 규칙 엔진의 "원전 글자 일치만 확인하고 해석은 확정하지 않음"이 서로를 잠갔다. M03의 모든 판정은 `partial/deferred`로 고정되어 LLM에 도달하지 않았고, F03 이후 기능은 "오행 개수표 + 점검 질문"만 남았다. 이 패턴으로 F02~F11을 완성해도 사용자가 받는 풀이 내용은 거의 없다.
2. 서술 검증기는 Mock에 맞춰 만들어졌고 실제 모델 호출은 프로젝트 전체에서 1회였으며 실패했다. 제목 완전 일치, 긴 근거 ID 복사, 문단 끝 글자 하나로 판정하는 문체 검사 등 실제 모델이 통과하기 어려운 조건이 많았고, 모든 실패가 `OUTPUT_REJECTED` 하나로 뭉개져 원인을 알 수 없었다.
3. 프롬프트는 금지 지시가 20개 이상인데 "무엇을 어떻게 써야 통과하는지"는 없었고, 모델에게 필요 없는 `inputPath`·`findingId`·URL·페르소나 기계 필드를 보냈다.

## 2. 재정의한 목표

"환각 없는 풀이"는 명리 지식 없이는 누구도 검증할 수 없다. 대신 다음을 **공학적으로 보장**한다.

| 목표 | 보장 수단 |
| --- | --- |
| **근거 추적** — 풀이의 모든 해석 문장이 어느 원전의 어느 구절에서 왔는지 연결된다 | 해석 단위(`InterpretationUnit`)가 원문 구절·요약·함의 검사 결과·출처를 함께 보관하고, 서술 계획의 근거 별칭(`E1…`)으로만 LLM에 전달한다 |
| **일관성** — 같은 원국 + 같은 카탈로그 버전 + 같은 캐릭터 → 같은 계획 | `planKey`(캐릭터 무관), `narrationKey`(캐릭터·모델·프롬프트 포함) |
| **금지 주장 차단** — 날짜·점수·내부 식별자·계획 밖 근거 | 거절 사유 코드가 있는 근거 검증(hard) |
| **정직한 표시** — 해석 요약은 "AI 요약·미감수" | 카탈로그 `reviewStatus`, 계획 한계 문장, UI 고지 |

"맞는 해석"은 보장하지 않는다. "출처가 있는 해석"을 보장한다.

## 3. 채택한 구조

```
① 원국 계산 (유지)  →  ② 관측·조건 (유지, M01~M03)
   →  ③ 해석 조회 [신설]  src/domain/interpretation      조건 키 → 퍼블릭 도메인 원전 구절 + AI 한국어 요약
   →  ④ 서술 계획 [신설]  src/domain/narration/plan.ts   캐릭터 무관 말풍선(beat) 계획, 근거 별칭, 한계
   →  ⑤ 렌더링   [재작성] src/domain/narration/render.ts 스타일 가이드 산문 + 출력 계약 + 예시, 근거 검증(hard) / 문체 점수(soft)
   →  ⑥ 전달      R01 JSON(개발자) 지금, R02 말풍선 스트림·TTS는 ④의 beat를 소비
```

- **지식 소스**: 궁통보감(일간 10 × 월지 12 = 120칸), 적천수 천간론(10), 삼명통회 십성론(5 + 조합 6). 모두 퍼블릭 도메인(Wikisource). 조건 키는 개발자가 코드로 소유하고(`scaffold.ts`), **원문은 수집 스크립트가, 요약은 생성 스크립트가** 채운다. 사람이 해석 문장을 타이핑하지 않는다.
- **요약 생성**: 원문 구절만 입력으로 받는 요약 호출 1회 + 독립 함의 검사 호출 1회. 함의 검사 FAIL은 저장하되 `usable=false`로 남긴다. `reviewStatus: ai-summarized-unreviewed`를 UI·계획 한계에 명시한다. 감수자가 생기면 `human-reviewed`로 올린다.
- **벡터 RAG는 보류**. 조건 키 조회표로 충분하며, R03 후속 질문에서 임의 질문→구절 검색이 필요해질 때 재검토한다.
- **기존 R01 경로 삭제**: `preparePersonaNarration`·`validatePersonaOutput`·`persona-mock`·`narrateCore`·`FeatureNarrationSpec`과 관련 테스트를 제거했다. 서술 경로는 한 벌이다.

## 4. AGENTS.md 원칙 수정

- 변경 전: "GPT-4o mini는 **확정된 판단만 설명**한다."
- 변경 후: "LLM은 **서버가 건네준 서술 계획(확정 관측 + 승인된 고전 해석 요약 + 한계) 안에서만** 문장을 만든다. 새 판단·계산·근거를 만들지 않는다."
- 유지: 명리 계산·판단은 규칙 엔진, LLM은 계산하지 않음, Mock 기본·Live 명시 승인.

## 5. 검증 정책 변경

- 근거 검증(계획 집합·별칭·길이·날짜·내부 식별자 노출)은 **거절 사유 코드**를 갖는 hard 게이트다. 거절은 `OUTPUT_REJECTED_<CODE>`로 기록한다.
- 문체 검사는 **soft 점수**(0~1)다. 실행을 실패시키지 않고 운영자에게 참고로 보인다. 높임법은 문장 단위·인용 제외·70% 비율로 본다.
- Mock 통과는 **배선 검증**이다. 품질 기준선은 WBS-71의 **실측 보정 루프**(18회, 사유 코드 분포 기록)로만 세운다.
