# OpenAI 서술 실험 · 비용 · 보안 — v2.4

## WBS-22 조직 설정 수동 확인

[혜택·동의·환경 분리 체크리스트](checklists/WBS-22-openai-account-review.md)에
조직 관리자 확인 항목, 비식별 증빙 양식, 정상/오류/경계 판정과 현재 미확인 상태를 기록한다.
체크리스트 준비 완료를 계정 혜택·공유 동의·환경 분리 적용 완료 또는 실호출 승인으로 간주하지 않는다.
혜택 자격과 한도가 미확인이면 계획상 무료 인정량은 0이다. 기본 Mock과 지정 모델은 유지한다.

## 운영 계약

- 모델: 서버 전용 `gpt-4o-mini`; 공급자 인터페이스로 분리하여 교체 가능한 구조. API 실제 가용성/지원 종료 일정은 개발·배포 시점에 다시 확인.
- 개발용 Data Sharing 혜택의 **일 250만 무료 토큰은 계정 확인 전 가정**이며 청구 면제 보장 아님. 내부 정책값 예시: 일 200만 토큰, 100회 호출. R02 한 리포트는 섹션마다 호출하고 R03도 누적되므로 사용자·세션·일 예산을 별도 적용한다.
- 기본 검증은 SDK Mock/SSE 시뮬레이션. **CI에서 외부 API 실호출 금지**. 명시적으로 승인된 개발 환경에서만 실 API 실험. 실제 고객 개인정보에 데이터 공유 설정 사용 금지.

## 입력·전송

1. 서버가 `FeatureResult`의 근거·불확실성을 사전 검증. 이름·정확한 출생일/출생지 같은 직접 식별정보는 필요하지 않으면 LLM에 전달하지 않는다.
2. R01 승인형 페르소나(버전), R02 서버 섹션 계획/근거 허용 목록, R03 동결된 분석 근거와 자신의 검증된 이전 대화만 사용한다.
3. 사용자 입력과 기존 대화는 **신뢰할 수 없는 데이터**. 개발자/시스템 정책과 동일한 우선순위로 합성하지 않는다.
4. 스트리밍 출력은 최종 검증 전 클라이언트에 노출 가능. 내용 검증을 보증한다고 주장하지 않는다. 위험 감지 시 중단/실패 처리하며 완료 후 영속화·질문 개방.
5. Responses API 저장 최소화 옵션(예: 지원 환경의 `store:false`)은 설치 SDK와 계정 환경을 확인하고 적용. **우리 Supabase 저장과 외부 API 저장 정책은 별개**임을 이용자 고지에 반영.

## 키·로그·권한

- `OPENAI_API_KEY`, Supabase service-role, PG 서버 키는 서버 측 비밀 환경변수. 클라이언트/코드/PR/로그에 절대 기록하지 않는다.
- 메트릭은 비식별 사용자 내부 ID, 기능 ID, 모델/프롬프트 버전, 호출 수, 입력·출력 토큰, 에러 코드, 지연 중심. 원국·질문 원문·생년월일을 일반 로그에 기록하지 않는다.
- 인증/소유권/이용 권한/중복 요청/질문 상한/동시성 잠금은 서버에서 실행하며 클라이언트 `userId`, `analysisId`를 무조건 신뢰하지 않는다.
- 요청 차단·비용 상한 초과·외부 API 오류는 비용 발생 전 또는 발생한 범위 안에서 명시적인 상태로 처리하고 무제한 자동 재시도를 피한다.

## 검증

- Mock: 각 SSE 이벤트 순서, 중간 연결 종료, 중복 세션, 오류, 응답 근거 이탈, 잘못된 페르소나 ID.
- 수동 실험: 승인된 본인 또는 동의받은 테스트 데이터만 사용, 실제 토큰/금액 기록, 프롬프트/모델 버전 추적.
- 정책: 명리학은 전통적 해석. 의료·금융·법률·관계/미래 사실을 확정하지 않고 AI 사용을 실제 인간 상담으로 위장하지 않는다.
