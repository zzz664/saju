# F02 성격·기질 — WBS-32

`observeTemperament(facts, subject)`는 검증된 원국 사실만 읽는 순수 함수다. F02 실행기는
M03 temperament의 관측과 기존 후보/보류를 선택하고 M09가 공통 결과를 조합한다.
원국·M01/M02는 요청마다 한 번, M03은 필요한 주제만 실행한다. F01에서도 같은 결과를 재사용한다.

## 채택 규칙

| 규칙            | 필요한 관측                           | 기질 검토 범위                                                |
| --------------- | ------------------------------------- | ------------------------------------------------------------- |
| natal-context   | 확정 일간/오행, 월지·본기·본기의 십성 | 일간·월지 맥락을 제시하며 단일 기호 성격 단정은 하지 않음     |
| resource-output | 인성군과 식상군의 서로 다른 실제 증거 | 정보 수용과 자기 언어로 표현하는 순서·속도를 실제 경험과 대조 |
| peer-authority  | 비겁군과 관살군의 서로 다른 실제 증거 | 자기기준과 공동 역할·규칙을 조율하는 방식을 실제 경험과 대조  |

두 복합 조건은 기존 M03 temperament의 `family-pair` 규칙과 십성군 표를 그대로 사용한다.
일간 자체는 비견 관측으로 넣지 않으며 장간의 존재를 가중 강도로 바꾸지 않는다. 한쪽 십성군만
있거나 같은 오행이 많아도 새 성격 판단을 만들지 않는다. 미성립은 반대 성향·성격의 결함을 뜻하지 않는다.
성별/대운 방향 기준값은 기질 판단에 사용하지 않는다.

원국 사실의 출처는 기존 manseryeok 공개 오행표·연해자평 십성/장간 분류를 유지한다.
복합 맥락은 M03의 삼명통회 출처 ID를 추적한다. 현대적 점검 문구는
`policy:f02-review-questions-v1`이며 원전이 보증한 성격 알고리즘이나 전문가 승인·과학적 성격 검사로 표시하지 않는다.

## 확정 관측과 부분 해석

`f02.observation.*`의 complete/confirmed/accepted는 **기호 관측 사실**을 뜻한다.
함께 제시한 점검 방향을 실제 성격·기질·능력·정신건강의 확정으로 바꿀 수 없다.
기존 `m03.temperament.*`의 candidate/deferred/review-required를 보존하며 확정 서술 목록에서 제외한다.
M01의 관법 충돌과 M02의 관계 검토 항목도 기존 모듈 상태/근거로 남긴다.

정상 입력도 M01/M03의 해석 한계를 유지하므로 F02 전체는 partial이다. 시각 미상은 알려진 기둥만
사용하고 시주 의존 관측을 제외한다. 일간/월주가 확정되지 않으면 관측을 만들지 않는다.
원국/필수 모듈 불가는 unavailable이며 새로운 성격을 생성해 보충하지 않는다.
각 판단에는 실제 evidence 경로/값, 출처·정책, 규칙 버전, 주의와 미상 예외가 포함된다.

F02 규칙/실행기 v1.0.0, F02 프로파일/M03 temperament 투영 v1.1.0이다.
기존 M03 엔진 v1.0.0·원국 JSON/해시·F03 규칙/서술 경로는 유지한다.
서버의 실행기 등록 표에서 F02/F03을 제공하며 테스트 전용 포트로 재정의할 수 있다.

## 검토 경로

`feature-json`에 `{featureId:"F02",birthInput,calculationPolicy}`를 표준입력으로 전달한다.
정상 부분 결과는 stdout JSON과 종료 2다. 입력/실행 오류는 기존 CLI의 고정 stderr 오류로 구분한다.
`buildFeatureNarrationInput(result)`는 엔진이 생성한 검증된 불변 결과에서 확정 관측만 투영한다.
Mock 소비자의 원국·근거 변경을 차단하고 외부 JSON 복사본은 투영 입력으로 받지 않는다.

이번 WBS는 CLI와 공통 서술 입력 계약까지다. `/dev/api-test`의 R01 Mock/Live 선택지는
core-base/F03이며 F02의 실제 Provider 연결이나 사용자 P06/SSE는 포함하지 않는다.
실제 API 호출은 하지 않았다(LIVE_NOT_RUN).
