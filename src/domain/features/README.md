# F03 오행·십성 강점·약점 — WBS-31

`strengths.ts`의 순수 `observeStrengths`는 기존 검증된 facts를 재사용한다. 새로운 역법·십성
계산을 하지 않는다. F03 실행기는 M03 strengths 투영과 기존 후보를 선택하고 M09가 원국·상태·버전을 조합한다.

## 채택 범위와 근거

| 규칙               | 성립 조건                                        | 출력 범위                                                      |
| ------------------ | ------------------------------------------------ | -------------------------------------------------------------- |
| elements-surface   | 확정 일간과 월주                                 | 알려진 겉글자 오행 개수 5개                                    |
| elements-hidden    | 확정 일간과 월주                                 | 알려진 지지의 지장간 오행 출현 개수 5개                        |
| resource-output    | 인성군과 식상군이 서로 다른 실제 증거에서 관측됨 | 학습·정리·표현의 강점 활용 질문, 준비와 실행의 균형 점검 질문  |
| authority-resource | 관살군과 인성군이 서로 다른 실제 증거에서 관측됨 | 역할 이해·자료/지원 활용 질문, 역할 요구와 학습 속도 조율 질문 |

두 집계는 단위가 달라 합산하거나 가중 점수로 바꾸지 않는다. 미상 기둥은 제외한다.
장간 순서/존재는 강도의 증거가 아니다. 두 십성군은 기존 M03 strengths와 동일한 분류를 사용하고
일간 자체를 비견으로 세지 않는다. 표에 없는 조합을 반대 성향이나 약점으로 해석하지 않는다.

출처는 facts의 manseryeok 공개 오행표·연해자평 장간/십성 분류를 추적한다. 개수는 기존
`policy:separate-unit-occurrences`, 질문은 `policy:f03-review-questions-v1`이다. 질문은 구현 정책이며
원전이 보증한 성격 알고리즘·전문가 승인·과학적 능력 평가가 아니다. 실제 성향/성과는 확정하지 않는다.

## 관측 사실과 해석 후보의 분리

`f03.observation.*`의 confirmed는 **기호·개수의 관측 사실**에 적용한다. 함께 제공하는 점검 질문을
개인의 실제 강점/약점으로 단정할 수 없다. 기존 `m03.strengths.*`는 candidate/deferred/review-required를
그대로 유지하고 확정 서술 목록에서 제외한다. M01의 관법 충돌/강약 미확정도 해결한 것으로 표시하지 않는다.

현재 F03 결과는 정상 원국도 M01/M03 해석 한계 때문에 partial이다. 코어/필수 모듈이 불가하면
unavailable이다. 관측 조합이 없으면 개수와 해석 한계만 반환하며 분량을 채우기 위해 성격을 생성하지 않는다.
모든 관측에 입력 경로/실제 값·출처·버전·주의·미상 예외가 포함된다.

F03 규칙/실행기 v1.0.0, F03 프로파일 v1.1.0, M03 strengths 어댑터 투영 v1.1.0을 추적한다.
기존 M03 규칙 엔진 v1.0.0과 코어 JSON/해시는 변경하지 않는다. 질문/투영 변경은 캐시 키에 반영된다.

## 검토

`feature-json`에 `{featureId:"F03",birthInput,calculationPolicy}`를 전달한다. partial/unavailable은
종료 코드 2, 입력/실행 오류는 기존 CLI 규칙에 따른다. 실제 GPT 문장 테스트는 보호된 개발자
`/dev/api-test`에서 F03을 선택한다. 가상 사례만 허용하며 기본 Mock, 실제 Live는 동의 후 명시 실행이다.
