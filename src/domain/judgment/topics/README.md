# M03 주제별 판단 — WBS-29

`evaluateTopic({facts, structure, relations}, topic)`는 확정 facts와 M01/M02를 재사용하는 순수 함수다.
주제는 `temperament | strengths | career | wealth | romance | social` 중 하나이며,
선택한 주제의 세 규칙만 평가한다. 원국·십성·관계를 재계산하거나 수정하지 않고 LLM/SDK/DB를 호출하지 않는다.
출력은 주제별 `TopicFinding[]`, 평가한 rule ID, 후보/보류·충돌·한계 및 독립 버전을 담는다.

## 주제 팩과 채택 조건

| 주제        | 두 검토 조건                        | 문구의 범위                                     |
| ----------- | ----------------------------------- | ----------------------------------------------- |
| temperament | 인성+식상 / 비겁+관살               | 학습·표현 / 자기기준·역할 조율의 기질 검토 후보 |
| strengths   | 인성+식상 / 관살+인성               | 학습·산출 / 역할 이해·지원의 강점 검토 후보     |
| career      | 관살+인성 / 식상+재성               | 절차·학습 / 산출·자원 관리의 업무 맥락 후보     |
| wealth      | 식상+재성 / 재성+비겁               | 산출·자원 / 공동관리·자기기준의 검토 후보       |
| romance     | 일지의 지지 결합 / 일지의 지지 대립 | 확정 일간·일지·월지와 관계 표지를 함께 검토     |
| social      | 비겁+식상 / 비겁+관살               | 동료·표현 / 동료·조직 역할의 검토 후보          |

각 팩의 세 번째 규칙은 높은 우선순위의 **맥락 검토/보류**다. M01의 혼재·미결 강약이나
관법 충돌, 관련 M02의 합/대립 공존·복수 합 상대가 있으면 낮은 우선순위 후보를 지우지 않고
`deferred`로 보류한다. 양쪽 finding ID와 `defer-candidates`를 기록한다. 연애에서는 M02의
일지 지지 검토 항목만 관련 관계 충돌로 사용한다. 다른 주제는 원국 전체 맥락을 검토한다.

십성군 후보에는 일간·월지와 서로 다른 두 군의 실제 관측 경로가 필요하다. 천간과 장간의
기존 십성을 재사용하며 일간 자신은 세지 않는다. 한 군의 반복·개수만으로 복합 조건을 만들지 않는다.
시주가 없으면 시주 증거를 쓰지 않고, 일주가 미확정이면 일간 상대 십성/일지 후보를 만들지 않는다.
미채택 조건은 반대 성향·능력 부족을 뜻하지 않는다.

## 고전 근거와 구현 정책의 구분

[삼명통회 권5](https://zh.wikisource.org/wiki/三命通會/卷五)의 인·식·관·재 분류와 복합 맥락,
[권2](https://zh.wikisource.org/wiki/三命通會/卷二)의 관계 표지를 참조한다. `catalog.ts`는 원전 확인
범위와 각 규칙의 채택 설명을 별도로 기록한다.

학습/표현/자원/역할/자기기준이라는 현대적 검토 문구와 두 범주 결합은 **명시한 구현 정책**이다.
고전에 그대로 있는 성격 검사나 검증된 심리·직업·재물·연애 예측으로 주장하지 않는다.
성별별 배우자성, 결혼/이별, 타인의 속마음, 부·손실·투자 결과, 특정 적직/취업 성과,
실제 능력이나 성격의 확정은 하지 않는다. 원전의 성별 역할·숙명적 단정도 실행하지 않는다.
현재 소스 대조/자동 테스트는 명리 전문가 승인이나 과학적 유효성 인증이 아니다.

M01 강약/격국/용신은 후보이며 M02 강도·합화는 미평가라는 제한을 유지한다. 주제 결과는
후보가 있거나 검토할 맥락이 있으면 `partial`, 일간 불명 또는 채택 규칙/검토 근거가 없으면
`unavailable`이다. 어떤 경우에도 확정 성향 결과로 승격하지 않는다.

## 검증과 재사용

입력은 동일 원국의 facts/M01과 정확히 네 natal 위치의 M02여야 한다. 다른 원국·기간·두 사람의
관계를 섞으면 거절한다. `parseStructureDiagnosis`/`parseRelationAnalysis`는 내부의 검증된
불변 결과를 재사용하고 외부 JSON은 원래 facts/참조와 대조해 의미 검증한다. 애플리케이션은
Zod 출력 경계를 유지하며 검증된 자식 참조의 동일성도 보존해 엔진 재실행을 피한다.
`schemas.ts`는 엔진 없는 구조 계약이며 단순 파싱만으로 외부 JSON 내용이 검증되지는 않는다.

각 finding은 rule/version/priority, 원전 ID, 실제 입력 경로·값, 예외·주의와 충돌 ID를 갖는다.
결과는 불변이며 우선순위 다음 ID 순으로 결정적으로 정렬한다. 주제를 바꿔도 upstream 자료와
기존 코어 해시는 바뀌지 않는다. 주제 규칙 ID는 `m03.contextual-topics@1.0.0`으로 추적한다.

`application/topics`의 `calculateTopic`는 기존 코어/M01/M02를 한 번 산출한 뒤 주제만 적용한다.
계산 불가면 `evaluation: null`과 기존 사유를 유지한다. 검토용 CLI:

```sh
npm run --silent saju -- diagnose-topic career < tests/fixtures/cli-input.json
```

정상 후보/보류도 종료 코드 2다. 빈 stdout+오류 stderr와 구분한다. M09/F01~F11 실행기,
사용자 UI/API·서술 경로는 이번 범위가 아니다. [완료 조건·검증 기록](../../../../docs/evaluations/WBS-29-topics.md)을 참고한다.
