# 서버 관리 페르소나 JSON과 승인 카탈로그

[설계 문서](../../../docs/11_캐릭터_페르소나_및_서술_설계.md)의 서버 관리 JSON + Zod + 불변 버전을 적용한다. 현재 등록은 로컬 개발자 테스트/평가용 합성 프로필이며 실제 제품 캐릭터 승인이 아니다.

| 구성                                                 | 역할                                                            |
| ---------------------------------------------------- | --------------------------------------------------------------- |
| [해요체 JSON](profiles/synthetic-haeyo.v1.0.0.json)  | 해요체 1.0.0 전체 설정. API에 있던 내용 그대로 이동             |
| [합쇼체 JSON](profiles/synthetic-formal.v1.0.1.json) | 합쇼체 1.0.1 전체 설정. 해요체를 상속하지 않음                  |
| [서버 승인 목록](synthetic-catalog.ts)               | 정적 JSON import, 승인 ID/버전과 현재 활성 버전 지정            |
| [공통 카탈로그](../../domain/persona/catalog.ts)     | 기존 승인형 Zod 로더 재사용, 활성 프로필 목록·정확한 버전 선택  |
| [API 조립](../../server/api-test-catalog.ts)         | 코어 사례/목차 구성과 공통 카탈로그 연결. 캐릭터 내용/분기 없음 |

추가 절차:

1. 검토할 프로필의 전체 내용을 새 버전 JSON으로 작성한다. 기존 ID/버전 파일의 내용을 덮어쓰지 않는다. 문체별 선호 표현·긍정 예시도 그 프로필의 register와 일치시킨다.
2. 서버 설정에서 JSON을 정적으로 import하고 `approvedManifest`에 승인된 ID/버전/JSON을 명시한다. 파일이 폴더에 존재하거나 스키마를 통과했다고 자동 등록하지 않는다.
3. `activeSelections`에 해당 ID의 활성 버전을 지정한다. ID당 활성 버전은 하나이며, 승인 목록에 없는 버전·중복 ID·추가 경로 필드 등은 거절한다. 이전 승인 버전은 manifest에 유지할 수 있지만 자동 최신 버전 선택/대체는 하지 않는다.
4. 공통 프로필/프롬프트/Mock 평가와 API 목록 검증을 실행한다. 카탈로그, 요청 조립기, 공급자, 화면에 캐릭터별 분기를 추가하지 않는다. 현재 로컬 카탈로그/설정 API는 최대 50개 활성 프로필을 지원한다.

API와 품질 평가 코드는 동일한 승인 카탈로그에서 두 프로필을 가져온다. `tests/fixtures/persona-style.json`은 순수 로더/문체 단위 테스트용 별도 fixture로 유지하며 API/품질 평가의 설정 원본으로 사용하지 않는다. 기존 평가 JSON/사람 점수는 과거 기록으로 보존한다.

제품 캐릭터가 승인되면 별도의 제품용 서버 manifest와 활성 버전을 `createApprovedPersonaCatalog(manifest, activeSelections)`에 전달하면 된다. 로컬 합성 승인을 제품 승인으로 승격하지 않는다. 제품 저장소/관리 화면/DB 연동은 아직 구현하지 않았다. 클라이언트 업로드·요청 경로·임의 JSON으로 서버 승인 목록을 만들지 않는다.

페르소나는 문체만 제어한다. 분석 근거와 analysisKey는 유지하고 프로필/버전 변경은 narrationKey에 반영한다. R01 내부 JSON과 R02/R03 텍스트 스트림의 계약도 유지한다.
